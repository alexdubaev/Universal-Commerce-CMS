# A0-UX: предложение до реализации

Статус: предложение и фрагменты desktop/mobile согласованы владельцем 20 октября 2026 сообщением «согласовываю». Реализация выполняется по IMPLEMENTATION-PLAN.md. Макет не является установленным интерфейсом или результатом пользовательской приёмки реализации.

## Сейчас → будет

| Сценарий | Сейчас в подтверждённом Directus | Предлагаемое поведение |
|---|---|---|
| Обычная форма категории | Дублируются статусы «Все изменения сохранены»; начальный пустой state может выглядеть как подтверждённое сохранение. Общая панель не даёт очевидного возврата к списку. | Одна строка состояния: «Нет несохранённых изменений», «Есть несохранённые изменения», «Сохраняем изменения…» или «Изменения сохранены» только после подтверждённой записи. Кнопки «Сохранить», «Отменить изменения» и «К списку категорий». Последняя уходит к списку; отмена касается только формы и подтверждает потерю ввода. |
| Конфликт двух вкладок | «Сохранить мои изменения» вызывает только чтение сравнения, а не сохранение; сейчас это действие вводит в заблуждение. Ответ 409 сохраняет введённое название. | Одно уведомление: «Эта запись изменилась, пока вы её редактировали. Ваши правки остались в форме. Сравните изменения перед сохранением». До решения конфликта обычные «Сохранить» и «Отменить изменения» недоступны. «Сравнить изменения» только читает и открывает сравнение: колонки «Ваш вариант» / «Сохранённый вариант», например поле «Название категории». «Оставить мои правки» обновляет снимок для существующей CAS-защиты и оставляет ввод в форме; затем «Проверьте форму и нажмите «Сохранить»». «Отменить мои правки» просит подтверждение и загружает сохранённый вариант. Ни одно действие сравнения само не пишет. |
| Результат записи не подтверждён | После успешного HTTP 200 с сохранёнными на сервере данными UI получил некорректный acknowledgement `{data:{}}` и показал сырой текст `Save acknowledgement does not contain the changed fields and version`, статус «Unsaved» и «Сохранение…». Свежий GET подтвердил, что значение записано. Это не потеря сети. | «Не удалось проверить, сохранились ли изменения. Введённые данные остались в открытой форме». Кнопка «Проверить сохранение» использует существующее чтение/сравнение; не повторяет POST и не перезагружает страницу. |
| Внутренний выход с изменённой формы | Браузер показывает системное «Есть несохранённые изменения. Покинуть страницу?»; внутренний переход не получает понятного штатного диалога. | Диалог Directus «Выйти без сохранения?» с пояснением о потере несохранённого ввода. «Остаться» безопасно отменяет переход, Escape делает то же; «Выйти без сохранения» продолжает переход. Браузерный `beforeunload` остаётся системным: его язык и текст задаёт браузер. |
| Отмена формы категории | Явного контекста отмены изменений категории нет. | Подтверждение «Отменить изменения категории?» объясняет, что будут отброшены только несохранённые изменения этой формы. |
| Встроенный редактор дочернего блока | В настоящем PagesSection: подписи «Тип: text», «Group content / Group main / Group button / Group items / Group system» и кнопка «Назад». При нажатии «Назад» URL и всё содержимое редактора остались неизменны. Переопределение секции уже показывает «Сохранить блок»; generic fallback использует «Сохранить». Live metadata подтверждает choices секции, но не содержит `text`. | Убрать «Назад». Сохранить существующую кнопку «Сохранить блок»; улучшить только общий fallback. Сопоставить известные типы только с поддерживаемыми metadata. Для этого неизвестного fixture показывать «Тип блока не распознан» и сохранять `section_type: 'text'` без изменения данных. Группам дать безопасные русские подписи. Родительская защита несохранённого ввода остаётся активной. |
| Fallback-экраны маршрутов | Проверены `/sections/a0_unknown_probe`: «Раздел «a0_unknown_probe» недоступен.»; у `/home_page/invalid-a0-address`: «Редактор главной страницы работает только с singleton-записью без ID в маршруте.» | Для неподдерживаемого раздела: «Этот раздел пока недоступен» и переход «К списку товаров» на существующий `/product-editor`. Для неправильного адреса главной: «Не удалось открыть главную страницу по этому адресу» и «Открыть главную страницу» на `/product-editor/sections/home_page`. |

## Область визуального предложения

HTML-макет показывает только перечисленные общие панели и диалоги, с ориентирами viewport 1536×1024, 390×844 и проверкой узкой ширины 320 px. Он статичный, с нейтральной Directus-совместимой палитрой; не является интерактивной приёмкой. Это предложение не перерисовывает поля форм и не утверждает, что перечисленные изменения уже реализованы.

Фактический runtime подтвердил две вкладки одной категории, ответ 409 с сохранением введённого названия, чтение по действию «Сохранить мои изменения», дублирующиеся сообщения, системное предупреждение браузера, описанное выше поведение PagesSection и точные fallback-сообщения обоих маршрутов. Generic без override проверялся отдельно: уже установленный тип компонента PageSectionEditor смонтирован во Vue appContext Directus с `labels: {}` и затем размонтирован; это вспомогательный harness, не зарегистрированный менеджерский экран и не подмена модуля/установка bundle. Он показал «Page sections», «Type: text», «Status: draft», «Order: 1», «Hidden», «Group content» и другие внутренние названия групп. После настоящей записи блока с HTTP 200 UI показал raw acknowledgement error и «Unsaved»/«Сохранение…», тогда как свежий GET подтвердил сохранённый заголовок; автоматический повтор POST не выполнялся. Подпись «Сохранить мои изменения» воспроизведена как открытие сравнения без POST.

## Кандидатный scope реализации после согласования

Один исполнитель, без параллельных правок shared-файлов. Предварительно затрагиваются `src/admin-shell.js` и `dist/admin-shell.js`, `src/page-sections.js` и `dist/page-sections.js`, `src/index.js` и `dist/index.js` только для fallback unsupported route и неверного адреса главной страницы, затем только необходимые адаптеры `src/sections/categories.js`, `home_page.js`, `pages.js`, `articles.js` и их `dist`-пары. Для общего редактора группы сопоставить явно: `group_content` → «Содержимое», `group_main` → «Основное», `group_button` → «Кнопка», `group_items` → «Элементы», `group_system` → «Дополнительно». Известные типы отображать по проверенным поддерживаемым metadata/choices. Неизвестный `section_type: 'text'` показывать как «Тип блока не распознан», сохраняя исходные данные. Тесты-кандидаты: `test/admin-state.test.mjs`, `test/page-sections.test.mjs`, `test/sections/categories.test.mjs` и тесты других адаптеров лишь при их фактическом изменении. Выбирать минимальный набор по подтверждённому поведению. `admin-state.mjs` менять только при доказанной необходимости. Не менять товарный редактор или регистрацию A5. Сохранить текущие ограничения CAS, чтения, разрешений и идентификации записи; не менять схему, данные и роли. `src` и `dist` должны оставаться соответствующими.

После согласования: узкие адресные тесты изменённого поведения, проверка настоящего Directus на desktop/mobile, независимое ревью и `node scripts/verify-local.mjs` на окончательном кандидате. Ни этот макет, ни ветка не устанавливаются в production.
