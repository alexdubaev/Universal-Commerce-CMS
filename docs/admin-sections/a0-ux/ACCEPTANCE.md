Трасса `evidence/runtime-results.json` сохраняет также неудачные попытки harness (неточная пунктуация, неверный selector, старый screenshot page, устаревшая cookie и ожидание клика по намеренно disabled-кнопке), а также реальные дефекты до закрытия. Итоговые closure-проверки помечены FINAL; эти попытки не считаются дополнительными независимыми PASS. Финальный контекст не зарегистрировал uncaught page errors. Ранее был единичный `Unexpected token <`, не воспроизведённый на финальной установке и при повторном открытии article/product tabs; диагностика сохранена отдельно.

## Ограничения

Runtime проверен существующим Administrator. Реальной роли менеджера нет; роли не создавались, права не ослаблялись. Это **не подтверждение manager RBAC**. Нативные системные экраны и все формы Directus не подвергались повторному аудиту; старые технические подписи вне точных A0-потребителей не объявлены устранёнными.

Пользовательская приёмка разрешает завершение commit/push/PR/merge по AGENTS; точные SHA и PR фиксируются финальным HANDOFF в issue #15 после интеграции. PR #14 не менялся. Production/deploy не затронуты. PRODUCTS-UX #16 отдельно назначен владельцем; начинать его только от принятого merge A0, с новым воспроизведением и согласованием.
