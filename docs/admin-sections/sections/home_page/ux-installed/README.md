## Отчёты и границы доказательств

- [runtime-native-final.json](runtime-native-final.json): финальный run 10, PASS на точных четырёх src/dist-файлах выпуска. Native forms, раздельные сохранения, настоящий CAS-конфликт, parent-stale, транспортные faults, media, анонимный отказ, сравнение и очистка. Контраст значений в сравнении — минимум 7,25:1.
- [runtime-live-attempt7.json](runtime-live-attempt7.json): фактические live SSR-эффекты заголовка, текста, изображения/описания, CTA, поиска и поискового title — PASS; возврат витрины к исходным данным — PASS. Общий результат этого раннего запуска FAIL: последующий тест выбрал переименованный тестовый блок по старому заголовку. Ошибка приватного сценария исправлена и закрыта финальным run 10. Последующие продуктовые правки касались только контраста и readonly-представления неиспользуемого OG-файла; storefront, hooks, gateway, write payloads и потребители не менялись. Не утверждается, что весь run 7 прошёл или что live-проверка повторялась в run 10.
- [cleanup-audit.json](cleanup-audit.json): ведущий независимо прочитал singleton и сравнил все полученные поля с исходными, кроме обновляемого hooks timestamp; все 45 точных ID собственных тестовых блоков из десяти журналов отсутствуют. Полного восстановления БД не было.
- Менеджерская роль — NOT RUN: подходящей существующей роли нет. Administrator и технический gateway проверены раздельно; права не расширялись.
- Настроенное значение OG-файла — unit regression PASS с сохранением исходного ID и исключением из payload; native configured-value case NOT RUN, потому что исходное поле пусто и для снимка его не заполняли.
- Нулевую/множественную cardinality и field-level permission boundaries проверяют детерминированные controller-тесты; повреждённое live-состояние singleton не создавалось.

Адресный opt-in probe и приватные журналы хранятся в `D:/codex/ucms-release-backups/a2-ux-25ca1089-4115-4e8f-aa5e-0a0a8100dcd1/`.
