Единый визуальный контракт: [../../DESIGN-SYSTEM.md](../../DESIGN-SYSTEM.md); общие серверные механизмы, доступ, CAS и ограничения: [../../CONTRACTS.md](../../CONTRACTS.md). Полная таблица **всех** физических полей с типом, обязательностью, списком допустимых значений, связями и настройками интерфейса Directus Studio — [fields.json](fields.json), сверенная по blueprint на HEAD `4b241f0`. Синтетические значения из [fixture.json](fixture.json) пригодны только для статического макета и не импортируются.

## Назначение

Singleton-редактор главной: обязательный hero, поиск, ссылки групповой заявки, SEO и порядок секций.

## Список и поиск

**Предлагаемый маршрут:** `/admin/product-editor/sections/home_page` — экран одной записи; сейчас он не зарегистрирован. Списка, `/+`, `/:id` и создания нет.

Откройте единственную существующую запись: таблицы списка, создание и delete нет.

- **Список и фильтры:** отсутствуют; это singleton-экран, не таблица.
- **Загрузка:** использовать установленный native singleton/data-service путь и запрашивать только поля редактора. До реализации сверить response shape и проверку cardinality с версией Directus в окружении; не предполагать array/list REST response. Отсутствующая или множественная запись блокирует редактирование; не создавать запись автоматически.
- **Пустое состояние:** сообщить об отсутствующей записи и передать исправление владельцу Directus; экран не предлагает создание.

## Карточка и поля

Порядок вкладок и полный перечень полей каждой вкладки:

- **Основное** — ``status,source_page (только для чтения),h1``.
- **Первый экран** — ``hero_title,hero_text,hero_image,hero_image_alt,hero_primary_button_text,hero_primary_button_url,hero_secondary_button_text,hero_secondary_button_url,hero_search_label,hero_search_placeholder,hero_search_button_text,hero_bulk_prompt,hero_bulk_link_text,hero_bulk_link_url,hero_excel_link_text,hero_excel_link_url,hero_photo_link_text,hero_photo_link_url``.
- **Секции** — ``sections → page_sections``.
- **SEO** — ``seo_title,seo_description,canonical_url,og_title,og_description,og_image,is_indexable,seo``.
- **Дополнительно** — ``translations,id,created_at,updated_at (только для чтения)``.

Служебные, вычисляемые и скрытые поля остаются только для чтения согласно `fields.json`. Подробная таблица соответствия полей: [FIELD-MAP.md](FIELD-MAP.md).

**Связи:** source_page→pages; sections→page_sections; изображения→directus_files. Один владелец общего page_sections editor для home_page и pages (A0).

**CAS/запреты:** Обычное сохранение полей home_page и версии предпросмотра/публикации — разные операции. Существующие POST /commerce/versions/:id/save и /promote обслуживают version workflow; ими нельзя сохранять обычную запись и ими нельзя менять live page_sections. В endpoint promote обязательны expected и mainHash, а capturedSections — необязательное echo-поле, которое сверяется с сохранённым снимком в delta версии. Этот снимок — метаданные версии, а не физические поля home_page. Он не блокирует отдельное изменение live page_sections, поэтому не обещать пользователю, что правки секций полностью изолированы черновиком главной. Проверить поведение version/preview/promote на тестовом Directus перед обещанием такого UX. Полей sections_source и sections_snapshot в схеме нет; не добавлять их. Разделять обычное сохранение, предпросмотр и публикацию.

## Состояния и граничные случаи

У каждой страницы отдельно обработать загрузку, пустой результат, запрет доступа, сетевую ошибку с повторной загрузкой, отсутствие связанной записи/файла, попытка уйти с несохранённым вводом, повторное нажатие «Сохранить» и мобильную ширину 390 px без горизонтального скролла формы. При CAS 409 сохранить локальный ввод и показать конфликт, не выполнять автоматический overwrite.

Нет/несколько singleton; обязательные hero поля; alt; неизвестный section_type; изменение порядка; конкурентные parent/child edits; stale version; мобильная форма.

Для полей изображения использовать штатный выбор файла Directus. Отвязка не удаляет сам файл. Не добавлять безвозвратное удаление. Для коллекции, доступной только для чтения, кнопки сохранения и создания отсутствуют либо заблокированы; отправка формы не вызывает изменение данных.

## Критерии приёмки

1. Экран загружает ровно одну запись через подтверждённый native singleton/data-service контракт; при нуле или нескольких записях редактирование блокируется. Нет списка, фильтров или пагинации.
2. Карточка показывает только перечисленные разрешённые поля; обязательность, типы и choices точно совпадают с fields.json.
3. Мутация возможна только при явно разрешённом CAS/endpoint; если контракт закрыт, экран остаётся только для чтения и не пытается обойти запрет.
4. Singleton не допускает создание/удаление. Никакие коллекции и schema не создаются.
5. конфликт CAS сохраняет введённый текст; право доступа/load/сетевые ошибки имеют отдельные состояния.
6. Изображение подбирается штатно; отсутствие изображения не ломает карточку; удаляется только связь при предусмотренном CAS.
7. Компактный desktop повторяет согласованный product editor; мобильная версия 390 px остаётся удобным.
8. Для секции подготовлен фокусный test command ниже; проверку в браузере имеет собственную область и отдельное разрешение на запись/publish, когда оно потребуется.

**Критерии по этой секции:** Открывается singleton без создание/удаление. CAS родителя и CAS секций независимы. Save отличается от preview/promote.

**Focused command после реализации:** `node --test directus/extensions/deere-shop-product-editor/test/sections/home_page.test.mjs`.  
**Публичная проверка, если нужна:** Preview главной только на изолированном тестовом instance и отдельной авторизации.  
**Макет:** [открыть вариант секции](../../mockups.html#home_page); макет задаёт расположение и стиль, точный контракт полей задаёт это ТЗ.

## Ограничение работ

Секционная реализация не меняет Directus схему и seed-данные, права доступа/roles, токены, worker/lead/order processing, Docker/deploy, frontend и публичный сайт или общий реестр секций. Несовпадение фактических контрактов означает остановку и передачу lead-интегратору; обход штатный PATCH Directus не допускается. Начать реализацию можно только после независимой постановки, проверки текущего пути extension и scope-lock allowlist.
