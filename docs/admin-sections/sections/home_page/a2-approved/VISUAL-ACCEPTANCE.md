## Фактические браузерные тесты HTML-образца

`python check_reference.py` рендерит HTML через Playwright Chromium без внешних ресурсов и проверяет работу табов, состояние, раскрытие групп, отдельное сохранение секции, SEO live snippet, overflow 1536/390, readonly/empty/conflict. Результаты в `reference-checks.json`.

## Обязательная визуальная приёмка реализации

В PR приложить **реальные** screenshots Directus, а не перепечатанные макеты:

- `actual-hero-1536.png`, `actual-hero-390.png`, `actual-sections-1536.png`, `actual-sections-390.png`, `actual-seo-1536.png`, `actual-conflict-1536.png`; при необходимости additional viewport 1024.
- Сравнить в парах и записать отличия по плотности, заголовкам, внутренним отступам, табам, readonly-состоянию, расположению изображений, media picker, сохранению child/parent.
- Нельзя утверждать, что demo snippet равен Yandex preview, или что HTML placeholder это native file picker.
- В обязательном пользовательском сценарии человек редактирует hero → сохраняет его, затем секцию → сохраняет отдельно. Для обоих действий доказать фактическое сохранение/restore на собственном тестовом экземпляре. Другие разделы CMS не изменять.

## Красные флаги при review

Дублированные заголовки или toolbar; 34 технических поля сразу в первом viewport; высокие пустые панели; браузерные select разной высоты; мобилка с горизонтальной прокруткой страницы; фиктивная «Опубликовать», когда backend contract не доказан; перестановка секций drag&drop без CAS, ложный единый Save; тестовые UUID в UI вместо ясных названий; ухудшение существующих товаров/категорий; замена native Directus SEO/file interface на кустарный виджет.
