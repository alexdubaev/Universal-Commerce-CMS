# Universal Commerce CMS · A2 «Главная страница»

**PREVIEW / NOT APPROVED.** Пакет для оценки владельцем, предназначен для будущего отдельного задания агенту. Пока не загружен на GitHub и не подтверждён к реализации.

## Назначение

Новый специализированный редактор `home_page` **в уже существующем Directus** — не новая CMS, не новая витрина, не новый page builder. После болезненного опыта с «Категориями» пакет содержит точный интерактивный образец и независимые критерии UX-приёмки **до разработки**.

## Что открыть

1. `home-page-reference.html` — автономный интерактивный макет. Работает офлайн; форма, вкладки, секции, версии (разъяснение), SEO и демосохранение без каких-либо запросов к CMS.
2. `home-hero-desktop.png`, `home-hero-mobile.png` — первый экран.
3. `home-sections-desktop.png`, `home-sections-mobile.png` — редактирование секций.
4. `home-seo-desktop.png`, `home-overview-desktop.png`, `home-conflict-desktop.png`, `home-search-expanded.png` — дополнительные состояния.
5. `TASK.md` — полное техническое задание агенту с ограничением объёма A2.
6. `VISUAL-ACCEPTANCE.md` — эталон/проверка соответствия.
7. `check_reference.py` и `reference-checks.json` — проверка **только этого демомакета**, не реальной CMS.

## Действия в макете

- Переключаются все пять вкладок с клавиатуры (←, →, Home, End).
- На «Первом экране» редактирование текста активирует demo «Сохранить»; поиск и заявки раскрываются отдельной кнопкой.
- На «Секциях» выбери блок, отредактируй его и отдельно нажми «Сохранить секцию»; это не меняет родительский save.
- На «SEO» изменение title/description обновляет иллюстративный сниппет.
- Кнопка «Версии» **ничего не публикует**: открывает описание отличия от обычного сохранения.
- Дополнительные состояния: `?tab=sections`, `?tab=seo`, `?tab=main`, `?state=conflict`, `?state=readonly`, `?state=empty`.

## Ограничения и риски, выявленные до разработки

1. `home_page` — singleton. Не должно быть таблицы, поиска, создания или удаления.
2. `PageSectionEditor` A0 не редактирует `sort_order`; не создавать fake drag-and-drop.
3. Parent fields, child sections и versions/promote являются разными CAS boundaries. Нельзя обещать единую атомарную публикацию.
4. Часть объявленных CMS hero/search/bulk/excel/photo полей не обязательно выводится текущей Next.js витриной; до реализации обязателен usage audit.
5. PR #6 по материалам исправления «Категорий» на момент подготовки ещё был открыт; после него проверять актуальное состояние main и стандарта UI.
6. Все данные на скриншотах вымышленные/демонстрационные. Фактическую реализацию можно считать принятой только после **реального runtime + visual QA**.

## Как работать после одобрения

Начать отдельное задание A2 по `TASK.md`. Создать чистую временную ветку/worktree от свежего `origin/main`. Использовать настоящий A0 и нативные Directus interfaces. Пройти локальный gate, настоящую проверку Directus/Chromium на изолированном окружении, сравнительное UI-review и independent code-review. Затем автоматические push/PR/merge и уборку своей ветки; deploy только на подтверждённый собственный target. В конце — один копируемый HANDOFF.
