# Техническое задание: Заявки (`leads`)

Документ описывает одну самостоятельную секционную задачу. Единый визуальный контракт: [../../DESIGN-SYSTEM.md](../../DESIGN-SYSTEM.md); общие серверные механизмы, доступ, CAS и ограничения: [../../CONTRACTS.md](../../CONTRACTS.md). Полная таблица **всех** физических полей с типом, обязательностью, списком допустимых значений, связями и настройками интерфейса Directus Studio — [fields.json](fields.json), сверенная по blueprint на HEAD `4b241f0`. Синтетические значения из [fixture.json](fixture.json) пригодны только для статического макета и не импортируются.

## Назначение

Просмотр отправленных заявок и ограниченная работа менеджера, не меняющая исходное обращение.

## Список и поиск

**Предлагаемые маршруты:** список `/admin/product-editor/sections/leads`, карточка `/admin/product-editor/sections/leads/:id`; создание `/admin/product-editor/sections/leads/+` только если это разрешено в CAS/permissions. Все они появятся только после регистрации общего маршрутизатора и сейчас не существуют.

Список и карточка являются предлагаемыми новыми UI-маршрутами; их ещё нет в Directus.

- **Колонки:** created_at,status,name,masked phone,product/category,lead_form.
- **Фильтры и поиск:** status,created_at,product,category,lead_form; поиск по персональные данные — только пользователю с соответствующим правом доступа.
- **Запрос:** запросить только необходимые для таблицы поля, фильтр и сортировку на сервере, с лимитом/страницей; не загружать всю коллекцию. Роли и права доступа Directus остаются авторитетными.
- **Пустое состояние:** объяснить отсутствие записей и предложить только доступное разрешённое действие.

## Карточка и поля

Порядок вкладок и полный перечень полей каждой вкладки:

- **Обращение** — ``status,name,phone,email,message``.
- **Позиции и файлы** — ``product,category,lead_form,request_items,attachments``.
- **Источник** — ``page_url,utm_source,utm_medium,utm_campaign,utm_content,utm_term,marketing_consent,marketing_consent_at,marketing_consent_version``.
- **Обработка** — ``manager_comment``.
- **Дополнительно** — ``request_key,request_fingerprint,user_created,id,created_at,updated_at (только для чтения)``.

Служебные, вычисляемые и скрытые поля остаются только для чтения согласно `fields.json`. Подробная таблица соответствия полей: [FIELD-MAP.md](FIELD-MAP.md).

**Связи:** product/category/lead_form relationships; attachments assets.

**CAS/запреты:** CAS отсутствует. G1 может разрешить только status и manager_comment с проверкой текущих ролей. Создание, удаление, контакты, message, consent, UTM, notifications и lead processing вне задачи.

## Состояния и граничные случаи

У каждой страницы отдельно обработать загрузку, пустой результат, запрет доступа, сетевую ошибку с повторной загрузкой, отсутствие связанной записи/файла, попытка уйти с несохранённым вводом, повторное нажатие «Сохранить» и мобильную ширину 390 px без горизонтального скролла формы. При CAS 409 сохранить локальный ввод и показать конфликт, не выполнять автоматический overwrite.

маскирование персональных данных; права на вложения; неизменяемое согласие; повторный request_key; экспорт; недоступная связанная запись.

Для полей изображения использовать штатный выбор файла Directus. Отвязка не удаляет сам файл. Не добавлять безвозвратное удаление. Для коллекции, доступной только для чтения, кнопки сохранения и создания отсутствуют либо заблокированы; отправка формы не вызывает изменение данных.

## Критерии приёмки

1. Таблица отображает заданные колонки, серверные фильтры и результат с корректной постраничная выдача.
2. Карточка показывает только перечисленные разрешённые поля; обязательность, типы и choices точно совпадают с fields.json.
3. Мутация возможна только при явно разрешённом CAS/endpoint; если контракт закрыт, экран остаётся только для чтения и не пытается обойти запрет.
4. Singleton не допускает создание/удаление. Никакие коллекции и schema не создаются.
5. конфликт CAS сохраняет введённый текст; право доступа/load/сетевые ошибки имеют отдельные состояния.
6. Изображение подбирается штатно; отсутствие изображения не ломает карточку; удаляется только связь при предусмотренном CAS.
7. Компактный desktop повторяет согласованный product editor; мобильная версия 390 px остаётся удобным.
8. Для секции подготовлен фокусный test command ниже; проверку в браузере имеет собственную область и отдельное разрешение на запись/publish, когда оно потребуется.

**Критерии по этой секции:** До G1 весь custom UI только для чтения; список раскрывает минимум PII, карточка — только авторизованному пользователю. Не отправлять test lead.

**Focused command после реализации:** `node --test directus/extensions/deere-shop-product-editor/test/sections/leads.test.mjs`.  
**Публичная проверка, если нужна:** Security/право доступа validation отдельна; тестовая форма не отправляет реальные данные.  
**Макет:** [открыть вариант секции](../../mockups.html#leads); макет задаёт расположение и стиль, точный контракт полей задаёт это ТЗ.

## Ограничение работ

Секционная реализация не меняет Directus схему и seed-данные, права доступа/roles, токены, worker/lead/order processing, Docker/deploy, frontend и публичный сайт или общий реестр секций. Несовпадение фактических контрактов означает остановку и передачу lead-интегратору; обход штатный PATCH Directus не допускается. Начать реализацию можно только после независимой постановки, проверки текущего пути extension и scope-lock allowlist.
