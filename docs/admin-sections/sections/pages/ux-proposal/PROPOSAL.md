# A3-UX-FIX «Страницы» — предложение для утверждения

Статус: **владелец утвердил показанный вариант и узкое расширение URL-scope 24.10.2026 сообщением «Утверждаю»**. Ниже сохранено первоначальное предложение; фактическая реализация и установка отражаются в A3-UX-PLAN.md и итоговой приёмке. BASE `22c2892e3ee632e0a08e0f9ba27bc47b7dc649bc`. Снимки `before-*` — установка на момент показа; `after-*` — отрисованный отдельный HTML. Макет не подключён к Directus и не является установленным результатом.

## Показанный вариант

- Четыре существующие вкладки: «Содержимое», «Блоки страницы», «Поиск и ссылки», «Дополнительно». Без новой навигационной системы и page builder.
- В содержимом — группы «Название и адрес» и «Содержимое»: название для списка, адрес, понятный тип; отдельно заголовок для посетителя, вступление, видимый текст внизу страницы. `seo_text` остаётся тем же значением, без миграции/преобразования. Надзаголовок раскрывается при необходимости.
- Новая страница — только черновик. Маленькая локальная транслитерация без зависимости предлагает `dostavka-i-oplata` для «Доставка и оплата». Ручной адрес перестаёт зависеть от названия; адрес существующей страницы не меняется автоматически. Заголовок посетителя не копируется из названия.
- Один основной scalar-ввод: заголовок/описание в поиске, показ в поисковых системах, изображение для ссылки; редкий основной адрес раскрывается отдельно. Дублирующая native SEO-панель не предлагается. Native поля и file library сохраняются. JSON fallback, no_index inversion, unknown keys, hook/readback и защита от гидратации сохраняются.
- Список сохраняет поиск, фильтры, сортировку и страницу при входе/возврате. Серверная пагинация по 25 остаётся. Убираются ложные алфавитные сортировки внутренних кодов статуса/типа; остаются дата изменения, название и адрес. Разные тексты для пустой коллекции, пустой выдачи и ошибки; создание только по подтверждённым правам.
- «Сохранить страницу» не меняет публикацию и не сохраняет дочерние блоки. Сохранение уже опубликованной страницы может изменить сайт после обновления кеша. «Изменить публикацию» — отдельный существующий workflow; статусы блоков не меняются автоматически. Для фиксированных about/delivery/contacts/payment предупреждение честно объясняет остающуюся встроенную страницу.
- Блоки используют существующий компонент A0/A2 и его opt-in представление; каждый блок имеет отдельный буфер/сохранение. Смена вкладки не теряет ввод. Parent-stale разрешается сверкой, а не фиктивным сохранением. Не добавляются создание/удаление/перестановка/публикация блоков, версии или preview.
- Системные страницы и source_page сохраняют прежнюю блокировку. Ошибки и сравнение используют понятные подписи; ошибка раскрывает нужное поле, ввод не теряется. Технические ключи в данных не переименовываются.

## Публичная ссылка: явное узкое расширение scope

Без новой подтверждённой зависимости корректный абсолютный URL в текущем приложении получить нельзя: CMS не получает NEXT_PUBLIC_SITE_URL процесса витрины; project_url / preview_url не заданы. Неверная относительная ссылка не считается исправленным сценарием. Рассмотренный вариант «только скрыть кнопку» не выполняет обязательную цель. Угаданный origin/порт, canonical_url и Host не подходят.

Предлагается **включить в первоначальное утверждение**:

1. Instance-local настройку `COMMERCE_STOREFRONT_URL`, без значения по умолчанию в общем коде и без секрета. Для подтверждённого локального контура её значение берётся из существующего проектного runtime витрины; сейчас документирован `http://127.0.0.1:3000`, процесс остановлен. При настоящей проверке сначала подтвердить запуск именно этого checkout/gateway/инстанции, затем работоспособность URL.
2. Один authenticated read-only endpoint `GET /commerce/config/storefront` в существующем commerce extension. Возвращает только проверенную базу витрины. Не меняет данные/схему/права/публикацию; не читает URL из пользовательского page content. Не раскрывает credentials. Не выполняет запросов на произвольный внешний адрес.
3. Редактор соединяет эту базу с **сохранённым** допустимым маршрутом **опубликованной** страницы; новая вкладка с noopener/noreferrer. Только HTTP(S), без credentials/query/hash; безопасная обработка префикса базы. Отдельно проверяются зарезервированные пути. Несохранённый slug не меняет ссылку. Черновик не имеет публичной ссылки, обычная ссылка не называется preview.
4. Если база не задана/небезопасна/не прочитана, «Адрес сайта пока не настроен» и конкретная зависимость вместо ложной активной кнопки. `state=configured` в макете — только иллюстрация будущей корректной настройки, не текущая готовность сайта.

Это явное предложение изменения backend/runtime-контракта для единственной зависимости A3. До утверждения оно не реализуется. Новое поле schema/DB и новый административный экран настроек не предлагаются.

Штатный deploy и адресный restart своего сервиса разрешены после утверждения по #19/#22; это не разрешение на дополнительные конфигурационные изменения.

## Target и проверка после утверждения

Target: только собственный **Windows Directus 12.1.1**, `http://127.0.0.1:18056`, Compose `universal-commerce-cms-dev`. Фактический bind проверен в PREPARATION.md. Production-target отсутствует и не выбирается. Локальная витрина этого же контура `http://127.0.0.1:3000` запускается штатным процессом проекта для сценария публичного URL и остаётся доступной на loopback после проверки, чтобы ссылка работала в установленном результате; её frontend не меняется. Сейчас этот процесс остановлен — текущая доступность не заявляется. Если подтверждение её принадлежности/безопасного запуска не проходит, значение базы не угадывается.

Нужные проверки: focused pages/SEO/list/URL/transliteration и затронутые A0/children regressions; authenticated configuration endpoint и anonymous denial; реальные native формы/GET/guarded save/status/readback/409/uncertain outcomes в Windows Directus; два блока и родитель без общего save; protected source/system pages; настоящая разделённая CMS/витрина и сохранённый URL; desktop/mobile сравнение с утверждённым макетом, адресно 1024/320, фокус/последние поля/контраст. Полезные проверки не заменяются source/CSS snapshots.

После этого одно свежее независимое code/visual review, bounded fixes, узкая closure, `node scripts/verify-local.mjs` на точном кандидате. Затем без повторного разрешения commit/push/PR/merge, проверка main, backup и исполнимый guarded artifact/config rollback без отката чужих новых записей, штатный deploy и post-deploy version/health/UI/URL screenshots. Финальный HANDOFF фиксирует факты. A4 не реализуется.

Текущие ограничения: пользовательского тестирования человеком нет; существующая подходящая manager role в прежнем runtime отсутствует и не создаётся для проверки. До утверждения продуктовые тесты/установка/review/публикация не выполняются.
