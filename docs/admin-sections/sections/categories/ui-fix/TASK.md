# A1-UI-FIX — Исправить список «Категории», не переписывая раздел

Репозиторий: https://github.com/alexdubaev/Universal-Commerce-CMS

## 1. Задача и границы

Исправь компоновку и удобство существующего списка категорий. Пользователь отверг текущий экран: громоздкие фильтры, растянутые элементы, неудобная таблица и вводящее в заблуждение сообщение о правах. Наличие тестов PASS не означает принятого интерфейса.

Одна задача: список /admin/product-editor/sections/categories и его фильтры. Карточку категории, создание, CAS, API, схему, permissions, зависимости и другие редакторы не переписывать. Не переходить к A2. Сохрани уже реализованную функциональность.

Визуальный ориентир — соседний файл categories-reference.html. Перед реализацией открой его в браузере и получи эталонные PNG desktop, mobile, filters, long-values; порядок указан в START-HERE.md. Это конкретный визуальный ориентир рабочего содержимого страницы. Оболочка Directus показана для контекста; не создавай по макету новые sidebar/rail и не меняй логотип. Демоданные, демонстрационные диалоги и клиентскую фильтрацию из HTML в CMS НЕ переносить. Реальные данные и запросы остаются существующими.

Выполни git fetch origin, проверь актуальный main и создай новую временную ветку/worktree от origin/main. Проверенная при подготовке задания версия: 9b810ff63e363c17c288f409cff6a25d9cc3de7d; это ориентир, не замена свежему fetch.

Прочитай AGENTS.md, docs/admin-sections/CONTRACTS.md, DESIGN-SYSTEM.md, sections/categories/A1-INTEGRATION.md и актуальные categories.js/admin-shell.js. Не повторяй исследование всей CMS и интеграцию A0.

Исходный checkout с чужими незакоммиченными изменениями не переключать, не stash/reset/clean. Один исполнитель меняет код; независимый reviewer проверяет результат.

## 3. Исправить причины, а не замаскировать симптомы

В проверенной версии:
- CategoryList передаёт AdminShell readonly:true независимо от реальных прав. Поэтому обычный список получает сообщения состояния редактора записи.
- Фильтры разделены между .category-filters и встроенными controls CollectionList.
- Поиск родителей и отдельная пагинация постоянно показаны в fieldset над таблицей.
- .category-filters использует flex, а label — grid без ограничения растяжения. Проверь computed styles: это кандидат на причину чрезмерной высоты полей.
- В categoryStyle есть неограниченные .ac-list__controls/.ac-shell-селекторы, потенциально затрагивающие общие компоненты.

Воспроизведи текущий экран на фактически загруженном кандидате и зафиксируй before. Не подменяй выяснение причины установкой readonly:false и не скрывай все предупреждения CSS.

## 4. Конкретная компоновка

Верх: один основной заголовок «Категории», рядом фактическое количество при доступном total; справа одна основная кнопка «Создать категорию», только по действующим правам. Native breadcrumb допустим; дублировать заголовок внутри нескольких toolbar не нужно.

Под ним одна строка:
[Поиск по названию, адресу или H1] [Все статусы] [Фильтры] [Изменённые недавно]

Поиск занимает свободную ширину, минимум около 280 px при достаточном месте. Контролы одной высоты: 40 px desktop, 44 px touch; отступы 8–12 px. На узкой области строка осмысленно переносится, а не сжимается до нечитаемых размеров. Высоту input/select нельзя растягивать до высоты соседней панели.

Сортировка — один контрол, объединяющий поле и направление. Сохрани ВСЕ действующие варианты, включая slug, parent, status, show_on_homepage, sort_order, updated_at. Убери отдельный постоянно видимый селект «Направление сортировки».

Кнопка «Фильтры» открывает компактную панель шириной примерно 360–380 px; на мобильном — адаптивную полноширинную панель. Внутри: родительская категория, показ на главной, индексация. Поиск родителя и подгрузка следующих вариантов находятся внутри открытого выбора, не на основном экране. Сохрани серверный поиск, UUID значения, ограниченный размер страницы и защиту от устаревших ответов; не загружай всю коллекцию.

«Применить» применяет выбранные фильтры; закрытие без применения сохраняет прежнюю выдачу. Активные дополнительные фильтры показаны компактными удаляемыми метками. Рядом доступен сброс. Смена фильтра/поиска возвращает страницу выдачи к первой. Escape закрывает панель, фокус возвращается кнопке открытия; фокус не уходит за пределы модальной панели.

## 5. Таблица, ширина и мобильный вид

Колонки: «Название и адрес», «Родительская категория», «Статус», «На главной», «Порядок», «Изменено».

В первой ячейке название — основной текст, slug — вторичная строка. Это объединение представления, а не удаление поля. Название и родитель занимают до двух строк, slug — одну с многоточием. Полные значения доступны через фокус/подсказку и открытие существующей карточки; одного hover для мобильного недостаточно. Длинные UUID не должны превращать строку в шесть строк текста.

Используй доступную ширину списка без пустой колонки медиа. Названию отдавай примерно треть ширины, родителю около пятой части. Обычная строка ориентировочно 60–76 px; не фиксируй высоту так, чтобы обрезать текст. Статусы компактные и текстовые, цвет только дополнительный признак. Даты форматировать по реальным значениям; null отображать «—», ничего не выдумывать.

Одна пагинация основной выдачи располагается снизу. Размер страницы 25, серверная фильтрация, сортировка и ограничения запросов сохраняются.

На 390 px — компактные строки списка: название/slug, статус, родитель. Остальные сведения остаются в существующей карточке. Не создавать второй источник данных или отдельный мобильный редактор.

Не отключай панель ИИ или навигацию Directus глобально ради хорошего скриншота. Проверь адаптацию с открытой и закрытой правой панелью. Сравнивай рабочее содержимое при одинаковой доступной ширине.

Ориентиры: основной текст 14–16 px, вторичный 12–13 px, заголовок 24–28 px; нейтральная тема Directus и существующий акцент. Не переносить цвета витрины и не добавлять декоративные метрики.

## 6. Права и минимальные изменения A0

Список не является формой редактирования записи: на нём не нужны «Все изменения сохранены» или общий «Режим просмотра» только из-за отсутствия inline-редактирования. Реальные ошибки чтения и ограничения действий должны оставаться видимыми и точными. Право создания и право изменения — разные проверки. Сообщение должно описывать именно запрещённое действие.

При необходимости добавь минимальный обратно совместимый режим списка в AdminShell и slots для controls/cells в CollectionList. Старые defaults и поведение редакторов сохранить. Не копируй всю таблицу или state machine в новый компонент только ради оформления.

Разрешённый scope:
- src/sections/categories.js и зеркальный dist;
- минимально src/admin-shell.js и зеркальный dist, только если доказана необходимость для list-mode/slots;
- адресные тесты categories/A0 и существующий runtime-проверщик;
- краткая запись о проверке в документации categories;
- короткое правило визуальной приёмки в корневом AGENTS.md.

Пути src/dist относятся к directus/extensions/deere-shop-product-editor/.

Не менять createCategoryController, buildCategoriesQuery, categoryPermissions, validateCategory, admin-state.mjs, page-sections.js, серверные контракты и маршруты ради вёрстки. Предусмотри корректное подключение новых элементов к существующим обработчикам. CSS ограничить оболочкой categories; не оставлять глобальные overrides нативных форм.

Parent в карточке остаётся readonly, удаление отсутствует. Это не задача на серверную защиту дерева. Тестовые записи не удалять «для красоты»: записи A1 на исходном скриншоте могли существовать во время проверки. Проверяй точный журнал владельца; в этой задаче очищай только собственные fixtures.

## 9. Завершение

Когда функциональная И визуальная проверки зелёные: commit → push → один PR → review → merge. Если main изменился, проверь актуализированный кандидат. Подтверди конечное дерево main, синхронизируй его безопасно и удали только свою объединённую временную ветку и чистый worktree.

Deploy выполняй самостоятельно только в подтверждённое собственное окружение с существующим rollback. Отсутствие такого окружения — DEPLOY BLOCKED, не разрешение создавать инфраструктуру. Не оставляй контейнер с mount на удалённый worktree. Не запускай заново широкий инфраструктурный аудит без новых оснований.

Финальный HANDOFF выдай одним копируемым Markdown-блоком: исправления, сохранённая логика, изменённые файлы, SHA/PR/merge, команды и результаты, фактические before/after desktop/mobile, вывод визуального reviewer, способ загрузки bundle, deploy или blocker, cleanup собственных fixtures/ветки/worktree.

Передай следующие правила: одна задача одному агенту; новая временная ветка от свежего main; независимые проверки допустимы параллельно; зелёные функциональная и визуальная приёмки разрешают автономный push/merge; только безопасный подтверждённый deploy; удаление только собственных объединённых веток; все ТЗ и хандофы — в копируемых блоках. После A1-UI-FIX остановиться.
