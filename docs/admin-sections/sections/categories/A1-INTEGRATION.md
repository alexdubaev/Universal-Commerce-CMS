## Delivered behavior and live contracts

Categories alone is registered. Product list links to the new section; original product list/create/edit and A0 namespace remain intact. List fields are explicit, requests use 25-row pages and stable sort with id tie breaker. Search composes an OR over title/slug/h1. Status, parent, homepage and indexation filters run on the server. Parent option search is independently paged; no full category catalogue is downloaded.

All four tabs use the A0 NativeFieldGroup/SectionTabs, with AdminShell, EditorToolbar, CollectionList/buildCollectionQuery, MediaPicker, ReadonlyDetails and createEditorState. Live metadata supplies types, required fields, choices, labels, options and readonly flags. `id/created_at/updated_at` are technical readonly values. No PageSectionEditor is needed for categories. JSON is passed as native JSON without reformatting SEO or other structures. After successful guarded writes the complete readable record is refreshed, because the existing SEO hook synchronizes JSON and scalar projections.

Live Directus 12.1.1 on the approved own `http://127.0.0.1:18056` confirms all 27 documented physical fields and draft default. Effective permissions come from `/permissions/me`, intersected with `/permissions/me/categories/:id` for update. Unknown rights fail closed. Actual read and mutation requests remain subject to native accountability. Existing Administrator is the authenticated runtime identity; no roles/users/permissions are created. Readonly and denied UI scenarios use controlled HTTP responses; real anonymous mutation denial is separately verified. This is not acceptance of an unprovisioned restricted role.

Live differences from the static snapshot: images use ordinary M2O metadata. A local display-only adapter selects native `file-image` inside A0 MediaPicker to open the actual Directus file library; the schema and folder policies are untouched. Unlink changes only the UUID field. Bounded selected-file lookups report missing/denied assets without silently clearing the relation. The live status interface is `input` with choices metadata; it is preserved and the choices are validated rather than replacing Studio configuration.

Update uses only `POST /commerce/mutations/categories/:id`, `{expected,changes}`. Expected contains original id, nullable updated_at and original values of dirty fields. Only changed permitted nontechnical fields are sent. Native PATCH is never used. Double submit is blocked. HTTP 409, network loss and malformed acknowledgement retain local values and block another write. Explicit comparison/reconciliation refreshes the baseline; it never automatically saves. Slug/status/redirect/indexation and SEO changes have visible site-impact warnings.

Native `POST /items/categories` is confirmed on synthetic drafts, including existing SEO hooks and required/default fields. The editor always sends status draft, without client-selected technical fields. An uncertain create locks another POST. An explicit recovery action performs an exact slug read with limit 2, shows any candidate without claiming ownership/success, and offers guarded navigation to that record. No new API or infrastructure was introduced.

**Parent blocker:** a guarded update between two exact owned fixture IDs successfully created a cycle on the current server; the probe immediately removed it. There is no transactional server cycle guard in the reviewed hook/API. All parent changes (including create parent selection) are therefore unavailable in this editor. A client-only descendant search would not solve concurrency and is not presented as protection. A separate protected backend task is needed to enable reparenting. Deletion is absent, including categories with children/products.
