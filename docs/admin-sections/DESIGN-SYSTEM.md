# Единый визуальный и поведенческий стандарт
## Основа
Утверждённый concept и реализованный редактор товаров: references/product-editor-concept.png, references/product-editor-final-desktop.jpg, references/product-editor-final-mobile.jpg. Админка использует нейтральную палитру Directus с фиолетовым акцентом. Цвета публичного сайта не переносятся в оболочку CMS.

## Оболочка и плотность
Desktop эталон 1536×1024: native rail около 54 px, боковая область около 225 px; header содержит название, состояние и действия. Две колонки, разрыв 24 px: форма 50–55%, медиа/контекст 45–50%. У полей стабильная ширина; пары только для коротких значений. Контекст без изображения не заполнять ненужными карточками или метриками. Главный экран показывает основную работу, остальное — вкладки.

Вкладки: Основное → содержание/состав → SEO (где существует) → Дополнительно. В каждой сущности своё число вкладок по существующим полям; технические поля в Дополнительно readonly. Для списков — одна таблица с лёгкими разделителями, поиск, разрешённые фильтры, сортировка, пагинация. Не запрашивать весь каталог; размер страницы 25, проверка 1000+ записей.

Mobile 390×844: native sidebar свёрнута; сначала поля, затем медиа; одиночная колонка; вкладки горизонтально прокручиваются; длинные таблицы имеют доступный горизонтальный scroll или компактные строки; header действия доступны и не перекрывают поля. На desktop 1024 px высоты короткие основные формы максимально помещаются; длинные формы честно прокручиваются.

## Общие компоненты
AdminShell, EditorToolbar, SectionTabs, NativeFieldGroup, CollectionList, MediaPicker, DirtyGuard, ConflictNotice, ReadonlyDetails. PageSectionEditor — один общий владелец для главной и страниц. Не создавать собственную библиотеку rich text, файлов, relationship picker, Flexible Editor или SEO plugin.

Native v-form получает явные подмножества fields; не передавать collection, если она возвращает полную форму и разрушает порядок. Локально исключать group/note, сохранять required/interface/options/readonly/conditions. Сортировка внутри вкладки последовательна. Не менять blueprint или глобальные поля ради layout.

## Действия
Контент: Сохранить; Опубликовать — только где есть status и проверен действующий контракт. Save не должен переводить draft в published. Версии страниц: отдельные Сохранить версию / Опубликовать версию с проверенным promote.
Операционные записи: действия по разрешённому контракту; не использовать кнопку Опубликовать для заявок/заказов/SEO-очереди.
До G1 в новых редакторах без guarded mutation — просмотр, понятный статус недоступности сохранения и доступ к существующему native экрану по правам.
Hard delete, массовое изменение, массовая публикация и импорт не добавляются.

## Обязательные состояния
Loading, empty, read error с Повторить, dirty, saving, saved, validation, 409 conflict, permission denied, missing asset. На 409 значения и вкладка сохраняются; пользователь сравнивает актуальные и свои данные, обновляет baseline после явного решения. Не отправлять прежний snapshot автоматически повторно и не показывать ложное успешное сохранение.
Клавиатура: видимый focus, labels, aria-current для навигации, доступные tabs, возврат focus после picker, ошибки рядом с полями. DirtyGuard защищает смену записи/раздела и закрытие страницы; корректно работает после успешного save.

## Ограничение макетов
HTML — интерактивный offline макет, все действия синтетические. Изображения концептов иллюстрируют расположение, не реальное содержание или наличие функций. Точные типы и обязательность — fields.json каждого раздела.
