# Пакет материалов для секций Directus

Дата подготовки: 2 октября 2026. Здесь находятся 14 секционных спецификаций, задания, карты полей, offline fixtures, макеты, общий дизайн-контракт, контракты API, схема и исследовательские заметки. Материалы автономны и сохраняют структуру ссылок.

- Начните с [плана](PLAN.md), [единого стиля](DESIGN-SYSTEM.md), [контрактов](CONTRACTS.md) и [списка заданий](TASK-INDEX.md).
- Откройте [автономные макеты](mockups.html) обычным браузером. Картинки в `concepts/` и `references/` служат дополнением; поля задаются ТЗ и JSON.
- Для реализации передавайте исполнителю LAUNCH нужного раздела вместе с этим каталогом материалов.
- Все 14 видимых бизнес-разделов и 9 вспомогательных коллекций описаны. Это материалы планирования: кроме ранее реализованного редактора товаров, другие 13 редакторов здесь не считаются реализованными.

## Рабочая база

Текущий проект — `D:/codex/Universal Commerce CMS`. Операционные инструкции всегда используют фактический текущий HEAD этого проекта и его отдельную чистую task branch/worktree; SHA и состояние ветки фиксируются непосредственно перед стартом. Старое состояние исходного проекта приведено только в [исторической заметке о происхождении](SOURCE-PROVENANCE.md) и архивном исследовании. Оно не задаёт базу или рабочий каталог будущей задачи.

Для совместимости разделы остаются в `directus/extensions/deere-shop-product-editor`; namespace продуктов и будущих секций сохраняет `/admin/product-editor` и `/admin/product-editor/sections/<collection>`. Это путь хранения и интерфейсный контракт, а не утверждение, что все редакторы реализованы.

Перед секционной задачей требуется принятый A0 и зафиксированные exports в `CONTRACTS.md`. G1/G2 остаются отдельными защищёнными границами. Синтетические fixtures предназначены только для макетов и никогда не импортируются в Directus.

Пакет фиксирует статический blueprint-снимок. Live schema, права, расширения и API проверяются в целевом экземпляре перед реализацией; при расхождении остановиться и сообщить владельцу.
