# Статьи СМ ТЕХНО: черновики и публикация

Тексты хранятся в существующей коллекции `articles` собственного Directus сайта. Источник текста для витрины — HTML-поле `content`. Поля Flexible Editor `content_blocks` и `editor_nodes` не являются источником публичной статьи: переход редактора на них в этой задаче не выполнялся. Schema и права не изменялись. Реальный импорт, публикация материалов и развёртывание сайта не выполнялись.

## Подготовленные материалы

Файл `profiles/smtechno/article-drafts.json` содержит три офлайн-черновика:

- «Как найти артикул запчасти и передать его поставщику».
- «Какие данные подготовить для подбора запчасти».
- «Как составить список запчастей для расчёта без лишней переписки».

В каждом тексте `status=draft`. Авторы и даты не придуманы и отсутствуют. Материалы объясняют подготовку запроса и использование каталога/заявки; они не подтверждены компанией и требуют проверки владельцем. В них нет рекомендаций по ремонту, установке или неподтверждённой совместимости. Если такие рекомендации добавляются позже, требуется профильная проверка.

## Офлайн-проверка импортера

Из корня репозитория:

```bash
node directus/content/import-article-drafts.mjs
```

Это режим по умолчанию: никакого подключения к Directus, авторизации или записи. `--dry-run` даёт тот же результат. Проверяется структура черновиков, выводится список планируемых slug. Существование slug в CMS в этом офлайн-режиме не проверяется.

Импортер использует существующий native `DirectusAdminClient`. Применение возможно только при явных `--apply` и `--confirm-own-instance`, точном `DIRECTUS_URL=http://127.0.0.1:18056` и явно заданном `--planned-date` в формате UTC ISO, например `YYYY-MM-DDTHH:mm:ss.sssZ`. Дата без времени, некорректная календарная дата и другой адрес отклоняются до авторизации. Значение даты ниже — шаблон, его необходимо заменить; пример не предназначен для запуска без отдельного разрешения на запись в собственный runtime:

```bash
node --env-file=dev/.env directus/content/import-article-drafts.mjs \
  --apply --confirm-own-instance --planned-date '<проверенная предварительная дата UTC ISO>'
```

`dev/.env` относится только к собственному изолированному инстансу сайта и не публикуется. Не используйте доступы другого проекта. Не выводите токены или пароли в терминал/документацию. Существующий клиент использует локальные `DIRECTUS_TOKEN` либо учётные данные администратора из окружения.

Перед созданием каждого материала native запрос проверяет только его slug без ограничения по статусу. Если такой slug уже существует, материал пропускается, в том числе опубликованный/архивный/черновой. Импортер не делает PATCH, не заменяет записи и всегда создаёт `status=draft`. Уникальность slug обеспечивается существующей schema; конкурентное создание может остановить импорт с ошибкой, но не перезапишет запись. Импорт не является общей транзакцией: при ошибке проверьте уже созданные черновики; повторный запуск пропустит существующие slug.

Существующая schema требует непустой `published_at` даже для черновиков. Поэтому при применении нужна предварительная дата. **Она не означает состоявшуюся публикацию. Перед сменой статуса на `published` замените или проверьте её как фактическую дату публикации. Не оставляйте предварительную прошлую дату для вновь публикуемого материала.** Офлайн-файл даты не содержит. Автор остаётся пустым, пока нет проверенного имени и согласования.

## Редактирование через Directus Studio

1. В собственном Studio откройте «Статьи» и нужный черновик либо создайте новый. Сохраните статус `draft`.
2. Заполните `title`, уникальный стабильный `slug`, `excerpt` и HTML-поле `content`. Для нового черновика schema потребует предварительный `published_at`; применяются те же правила проверки даты перед публикацией. Не используйте `content_blocks` как замену `content`.
3. Используйте заголовки H2–H4, абзацы, списки и таблицы. Единственный H1 на странице формирует название статьи. Скрипты, события, iframe и опасные URL витрина не отображает. Текст должен оставаться понятным без изображения.
4. Для `cover_image`/`og_image` выберите проверенное изображение из уже разрешённой публичной папки собственного инстанса. Укажите содержательный `image_alt`. Встраиваемые изображения ограничены разрешёнными обложкой/OG статьи; не рассчитывайте на произвольные внешние URL.
5. Заполните `seo_title` и `seo_description` по содержимому. Не добавляйте неподтверждённые преимущества, условия доставки, статистику или экспертность. Удалите отметку о черновике из вступления только после согласования текста.
6. `author` заполняйте только при наличии проверенного автора; не придумывайте эксперта, опыт или проверку. Связанные категории и товары укажите через существующие JSON-поля `related_categories` и `related_products`, используя реальные проверенные идентификаторы, без изменения schema. Проверяйте доступность ссылок на опубликованные категории и товары.
7. Перед публикацией проверьте текст, ссылки, изображения и фактическую дату `published_at`. Затем осознанно смените статус на `published`. Будущая дата означает отложенную доступность: статья не появится до наступления указанного времени.
8. Проверьте `/articles`, `/articles/<slug>`, метаданные и sitemap. Смена статуса обратно на `draft` или `archived` убирает материал и его исключительные изображения из публичной выдачи. Изображение, также используемое другим опубликованным материалом/товаром, сохраняет разрешённую публичную ссылку.

Публичная статья доступна только при `status=published` и наступившей валидной `published_at`. Gateway независимо закрепляет эти условия на сервере, ограничивает поля и фильтры, разрешает до 24 материалов в обычном запросе и до 500 только в узком sitemap-запросе `fields=status,slug,published_at&sort=slug` (также разрешена проекция `slug,published_at`; адаптер дополнительно проверяет полученный `status`). `filter_count` учитывает те же условия публикации. Для статей начало страницы ограничено окном в 1 000 000 записей: `(page - 1) * limit <= 1000000`, поэтому максимальная страница равна `floor(1000000 / limit) + 1`. Пределы остальных коллекций не меняются. Чтение изображения требует одновременно разрешённую папку и опубликованную наступившую ссылку `cover_image` или `og_image`. Витрина использует `/api/assets/<UUID>`.

Дата публикации сохраняется в CMS и не обновляется при открытии страницы или сборке. Автоматическое техническое `updated_at` не выдаётся за редакционную дату обновления. Реальные права native Directus и состояние собственного runtime в этой работе не проверялись и не менялись; это локальная реализация gateway, адаптеров и редакционного процесса.

Sitemap статей читает коллекцию порциями по 500 с фиксированным порогом даты публикации; допускается до 48 000 статей, чтобы оставить место статическим URL в пределах 50 000 URL одного sitemap. Если коллекция больше или источник повторяет страницы, статья-секция sitemap закрывается без частичной выдачи. Для большего объёма потребуются отдельные article sitemap chunks и изменение sitemap index. Публичная пагинация списка ограничена отдельно описанным окном записей.
