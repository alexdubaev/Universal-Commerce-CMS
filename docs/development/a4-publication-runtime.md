# A4 publication guard — Directus 12.1.1

The previous live acceptance found a published Article with a future publication date in the protected storefront gateway. Directus 12.1.1 resolves only the first operation in a field expression; `published_at: { _nnull: true, _lte: now }` therefore applied only the non-null check.

The shared Article publication predicate now uses `published_at: { _lte: now }`, alongside the existing published status. PostgreSQL timestamp comparisons exclude NULL. The same predicate protects Article rows, counts, sitemap projections, cover images and OG image references. Authentication, query validation, schema, permissions, dependencies and the storefront are unchanged.

The gateway test boundary now reproduces the installed Directus first-operation behavior. Before the fix, actual route-response assertions failed for future rows/counts and future-only assets. After the fix, all 21 focused gateway tests pass. `node scripts/verify-local.mjs` passed with 241 backend/extension checks, 36 storefront checks, zero audit vulnerabilities, production build/type/token checks and two Chromium journeys. One independent security/code review found no blocking issues.
